> 盤點日期：2026-09-27（Round 12），依據倉庫內的程式碼，不是依據舊計畫的勾選狀態。
> 舊的 `src/app/(games)/shenmaSanguo/doc/implementation_plan.md` 很多沒打勾的項目其實已經完成，以本文件為準；舊文件保留當作歷史設計紀錄。

## 1. 分類說明

- **已有**：程式已實作，並且有測試或實際畫面可以驗證。
- **部分完成**：有實作，但和舊計畫描述的行為不同，或只完成一部分。
- **未實作**：程式裡找不到。

## 3. 已實作的技能

### 趙雲「奇襲」（Round 12，第一版）

| 項目     | 內容                                                                                                                                                                                          |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 規則     | 每場戰鬥中，趙雲第一次命中敵人的普通攻擊造成 2 倍傷害，之後恢復普通攻擊（攻擊力 100：第一擊 200，之後 100）。倍率交給既有的傷害計算，沒有改敵人減傷或其他武將                                 |
| 何時用掉 | 只有真的對有效目標發出攻擊才用掉；沒有目標（例如備戰中）不會用掉                                                                                                                              |
| 何時重置 | 同一場戰鬥裡，換波次、移動位置、更新隊伍或屬性、移除後重新放置都不會再觸發；切換關卡或同一關重來（新的 `battle_id`）才重置                                                                    |
| 範圍     | 主頁與獨立戰鬥頁都有效；其他武將與塔不變                                                                                                                                                      |
| 規則來源 | Web 的 `utils/heroSkills.ts` 是唯一來源：武將列表／詳情的說明文字，和隨出征資料 `team_list[].skill` 送進 Godot 的參數（`first_strike`、倍率 2）都由它產生；Godot 不認得的技能一律當作普通攻擊 |
| 存檔     | 技能是戰場效果，不寫進玩家存檔，也沒有改 GAS／Sheets 的結構                                                                                                                                   |
| 畫面     | 武將列表顯示「技能：奇襲」，詳情顯示完整規則；觸發時趙雲上方出現放大的金色「x2!」（Godot 專案沒有中文字型，畫布裡的中文會顯示成方框，所以不用「奇襲」兩個字），敵人頭上的傷害數字是 2 倍      |
| 驗證     | Godot 測試 R12-1～R12-9（用敵人血量變化斷言實際傷害）、反向驗證、瀏覽器 `r12-web.js`；結果見基準文件 §20                                                                                      |

### 黃忠「百步穿楊」（Round 14，第一版）

正式設定（Codex 2026-09-28 唯讀讀取 `get_heroes_config`，沒有玩家金鑰、沒有寫入）：`hero_id=huang_zhong`、`job=archer`、紫色、花費 6、基礎攻擊 92、射程 5、射程成長 0.03、攻擊間隔 1.9；設定裡的 `passive`「百步穿楊：超遠距離」只是說明文字，效果由這次的程式實作。設定另有 `speed_growth`（0.01），和程式使用的 `atk_spd_growth` 名稱不同，本輪沒有處理。

| 項目     | 內容                                                                                                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 規則     | 戰場上的有效射程 ＝（基礎射程 ＋（等級 − 1）× 射程成長）× 1.5：Lv1 7.5 格、Lv2 7.545 格、Lv3 7.59 格。普通攻擊的傷害與攻擊間隔不變，不加連射。1.5 是 Round 14 選定的第一版設計值，還沒做過平衡                                       |
| 不疊乘   | Godot 的 `Hero.gd` 在放置與 `update_team`（更新隊伍、升級）時都從基礎值重新計算再乘倍率（`_compute_range`），不在目前的值上再乘；移動位置、移除後重新放置、新的一場都一樣                                                            |
| 規則來源 | Web 的 `utils/heroSkills.ts`：列表／詳情的說明、詳情裡的實際射程（`effectiveRange`），和送進 Godot 的參數（`{ id: "long_range", range_multiplier: 1.5 }`）都由它產生。每種技能只帶自己的參數；Godot 不認得的技能 id 一律當作普通攻擊 |
| 畫面     | 武將列表顯示「技能：百步穿楊」；詳情寫出規則與目前等級在戰場上的實際射程（例如「射程 5 格，戰場上是 7.5 格」）。屬性表的「範圍」仍是原始數值；戰場上選取黃忠時，射程圈與既有的武將資訊面板都用實際射程                               |
| 存檔     | 技能與加成後的射程只在戰場；存檔、session、`save_result` 維持原始屬性，沒有改 GAS／Sheets                                                                                                                                            |
| 驗證     | Godot 測試 R14-1～R14-11（速度 0 的敵人放在指定格數，斷言實際扣血與邊界、傷害與攻擊間隔不變、各種更新不疊乘）、反向驗證 7 種錯誤實作、功能前對照、瀏覽器 `r14-web.js`（主頁實際部署、兩個入口、戰鬥中升級）；結果見基準文件 §22      |

## 4. 已知問題（Round 12 發現，既有）

| 問題                                                                                                                                    | 狀態                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Godot 專案沒有中文字型：畫布裡的中文都會顯示成方框（例如地圖兩端的標記、沒有貼圖時的武將名稱）                                          | 未處理；加入中文字型會讓遊戲檔案變大，而且要確認字型授權，另外安排                                                                       |
| 獨立戰鬥頁的遊戲 iframe 在頁面程式載入前就開始載入；遊戲比頁面先準備好時，只送一次的 `game_ready` 會被漏掉，頁面一直停在「載入戰場中…」 | 已修正（Round 12）：頁面掛上訊息監聽後送 `request_ready`，遊戲再回覆一次 `game_ready`。主頁的 iframe 在 React 掛載後才建立，沒有這個問題 |
