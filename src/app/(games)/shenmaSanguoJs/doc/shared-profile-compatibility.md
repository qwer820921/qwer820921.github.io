# 神馬三國 JS 版與 Godot 版的共用存檔

JS 版（`/shenmaSanguoJs`）和 Godot 版（`/shenmaSanguo`）用同一個玩家金鑰 `shenma_player_key`、讀寫同一份雲端存檔。這份文件說明 JS 版目前怎麼讀寫這份存檔、哪些情況會停下來，以及還沒完成的部分。

## 保存格式

- 唯一的保存格式是後端與 Godot 版的存檔（後端 `get_profile` 回應的 `data`）。JS 版把它原樣留在記憶體（`canonical`）並記住已確認的版本 `rev`。
- 畫面用的是另外算出來的顯示資料（`utils/sharedProfile.ts` 的 `projectSharedProfile`），只給畫面看，**不會寫回雲端**：
  - 武將清單照後端武將設定（`get_heroes_config`）列出兩邊都有的武將；存檔裡有升級紀錄就用存檔的數值（0 照樣是 0），沒有就用設定的基礎值（等級 1）。
  - JS 版內建的預設值（點數 1500、容量 65、13 位武將與預設隊伍）只用在訪客，不會出現在共用存檔。
- 武將 ID 只用明確的對照表轉換：後端的 `guan_yu` 對 JS 版的 `hero_guan_yu`，兩邊都有、各只出現一次才配對，不對任意字串加或去掉 `hero_`。
- 存檔裡 JS 版對照不到的武將，以及同一位有兩筆以上紀錄的武將，原樣保留，畫面不列出（不猜數值）、不能升級或出征。
- 雲端的隊伍（`team`，可以沒有）如果有對照不到的武將、`hero_id`／`slot` 以外的欄位、`slot` 不是 1 以上的整數或重複、同一位武將兩次、超過 5 位，就原樣保留，暫停在 JS 版修改隊伍與出征，不會換成預設隊伍。
- 存檔缺少 JS 版畫面需要的欄位（等級、經驗、點數、容量、最高關卡、武將陣列）或型別不對、版本不明、武將設定讀不到時，整份只能看、不寫入。

## 讀取與建立

- 開頁時有 `shenma_player_key` 就唯讀讀取；讀取、保存與載入都不會改這把金鑰，只有成功的登入、建立、切換與登出會改。舊的 `shenma_js_player_key` 與舊的 JS 本機存檔不再用來決定帳號。
- 雲端找不到存檔（404）時只說明找不到，要再按一次「建立新存檔」才送 `create_profile`；讀取失敗（網路、伺服器錯誤、存檔損毀）一律不建立。
- 建立時金鑰已經有存檔：改為讀取那份存檔。建立的結果不明：只唯讀查一次，不自動再建立。

## 寫入

- 改暱稱、改隊伍：在 `canonical` 的副本上只改 `nickname` 或 `team`（後端的 `hero_id`、`slot` 從 1 起，隊伍 cost 用後端武將設定的 `cost` 與存檔的 `capacity` 檢查），帶已確認的 `base_rev` 整份 `save_profile`。其他欄位，包括不認得的欄位與武將，逐項保留。版本不明時不寫入。
- 武將升級：`upgrade_hero` 帶後端的 `hero_id` 與 `base_rev`，點數與屬性由伺服器計算，成功後唯讀讀回完整存檔；讀回確認之前不算完成。JS 版不先自己扣點數或加屬性。
- 保存的回應沒有合法的新版本：唯讀讀回確認，確認之前不說已保存。
- 一次只進行一個寫入；寫入中的按鈕停用。
- 版本衝突（409 `REV_CONFLICT`）：改用雲端回應的資料並說明剛才的修改沒有保存，不用新版本自動重送；回應沒附資料時唯讀讀回，讀不到就標示「結果待確認」。
- 錯誤的分類：後端在寫入之前就回應的錯誤（格式不對、版本不符、找不到存檔、點數不足、忙碌等）才當成「沒有保存」；網路或平台錯誤、伺服器執行時的錯誤（`SERVER_ERROR`，可能在寫入之後才發生）、不認得的錯誤都當成結果不明：不重送，標示「結果待確認」，按「手動同步」唯讀讀回之前不開下一個寫入。建立存檔的結果不明時只唯讀查一次。
- 切換帳號、登出或重新載入後，前一個帳號遲到的回應（包含寫入之後的讀回）不會套用到畫面，也不會改變新帳號的保存狀態。
- 匯入覆蓋在共用帳號停用；匯出的是雲端存檔原樣（金鑰、版本與 `data`）。

## 戰鬥結算（尚未寫入共用進度）

兩版的戰鬥獎勵、星數、解鎖與升級費用規則要一律照 Godot 版與後端；對齊之前，JS 版共用帳號的戰鬥結果**不寫入雲端**：勝負都沒有獎勵、不解鎖關卡，結算畫面照實說明；「下一關」只在雲端已確認的進度裡已經解鎖時才出現，還沒解鎖時改說明並指向「選擇關卡」（既有的自由演練照舊，不代表解鎖）。`utils/sharedProfileSync.ts` 已有結算請求的規則（`settle_contract` 2、每場固定 `request_id` 與 `base_rev`、`base_mismatch` 要唯讀讀回而不是當成沒保存、重複送出不重發獎勵、`RESULT_UNKNOWN`／`REQUEST_ID_REUSED` 不換 id 重送），目前只有單元測試，還沒有接到畫面。

## 訪客

訪客只用這個瀏覽器的 `shenma_js_guest_state`（與 `shenma_js_guest_active` 標記），不連雲端、不改共用金鑰，也不碰 Godot 版的本機快取；規則照 JS 版原本的本機規則。

瀏覽器契約測試要由 runner 在 `page.context().__canvasContract` 提供 `createProfileFixture`、`baseUrl`（本機提供 `out/` 的網址）、`newContext({ viewport })`（正式站的資源由 `out/` 回應、其他外部網路擋下）與 `evidenceDir`（截圖目錄，可省略）。GAS 請求全部由 fixture 在測試程序內回應。

## 還沒完成

- 戰鬥結算寫入共用進度（見上）。
- JS 版沒有的武將（例如只在後端設定的武將）不能顯示、升級或出征；含這些武將的隊伍只能原樣保留。
- 讀取到的存檔格式問題只會唯讀，不提供修復。
