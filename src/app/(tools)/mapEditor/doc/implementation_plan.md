# 地圖編輯器 Implementation Plan

**建立日期：** 2026-04-20

## 功能概述

可視化塔防地圖編輯器工具，讓設計者能直覺操作格子並輸出 JSON 供神馬三國使用。

## 功能規格

| 功能          | 說明                                         |
| ------------- | -------------------------------------------- |
| 格子尺寸      | 自訂 cols × rows（最大 40×40）               |
| 工具：航點    | 按點順序新增，第一個=出生點，最後一個=終點   |
| 工具：防禦區  | 拖曳塗色（綠色）                             |
| 工具：障礙物  | 拖曳塗色（灰色）                             |
| 工具：清除    | 單格清除                                     |
| tile_textures | 固定 5 個欄位（road/build/empty/base/spawn） |
| 輸出          | 標準 JSON + Google Sheets 跳脫格式           |

## 輸出 JSON 結構

```json
{
  "map_id": "chapter1_1",
  "name": "第一關",
  "chapter": 1,
  "cols": 14,
  "rows": 11,
  "waypoints": [
    [0, 2],
    [11, 2],
    [11, 6],
    [2, 6],
    [2, 9],
    [13, 9]
  ],
  "spawn": [0, 2],
  "base": [13, 9],
  "build_zones": [
    [3, 1],
    [4, 1]
  ],
  "obstacles": [
    [0, 0],
    [1, 0]
  ],
  "tile_textures": {
    "road": "tile_road.webp",
    "build": "tile_build.webp",
    "empty": "tile_empty.webp",
    "base": "tile_base.webp",
    "spawn": "tile_spawn.webp"
  }
}
```

## 設定連動（Sheet）

- 讀取：「載入清單」讀 `get_all_maps`（含路線與波次），「載入」讀 `get_map_config`；都是唯讀，不需要管理密碼。
- 更新既有地圖（「更新至 Sheet」）：`update_map_config` 送 `map_id`、`path_json`，以及有修改的 `name`／`chapter`／`unlock_stage`（放在頂層；後端只把頂層的這三欄寫進 `maps_config`，`path_json` 裡的同名欄位不算）。沒有修改的欄位不送，後端保留原本的格子；章節只接受 1 以上的整數，其他寫法留在畫面上，不問管理密碼也不送出。成功後只讀地重新讀回這張地圖與已讀取的清單。
- 回應不明（連線中斷或回應看不懂）時不自動重送，畫面提供「重新讀回（只讀，不重送）」確認設定的內容；保存成功但讀回失敗時也一樣。讀回期間又改了畫面時保留這些修改。
- 地圖與波次分開保存（「更新至 Sheet」與「儲存波次至 Sheet」）；保存地圖後的讀回不會蓋掉畫面上尚未保存的波次。
- 先後：按「載入」後、回應回來前又改了畫面（地圖、地圖資訊或波次），或建立新地圖、匯入 JSON 時，較慢回來的載入不套用（新地圖與匯入會取消進行中的載入），保留較新的畫面；要換成那張地圖就再按一次「載入」，按下時畫面上尚未保存的內容會被取代並在訊息說明。保存的回應回來前已經換成別的畫面時，讀回照樣進行、結果照樣說明，但不改目前的畫面與原值。訊息都寫出地圖的 `map_id`；狀態列被較新的操作取代時，較舊操作的結果列在「其他操作的結果」。
- 波次：送出前濾掉沒有選敵人的組與濾完沒有組的波次（不補敵人、不重新編號，`utils/waveSave.ts`）。成功後只讀地讀回波次，以設定裡實際的波次為「已保存」的基準：期間沒有修改時畫面換成讀回的波次並說明哪些組沒有保存，期間又改了就保留修改並標示尚未保存。讀回失敗與結果不明時不自動重送，提供「重新讀回波次（只讀，不重送）」。
- 解鎖條件（`unlock_stage`）只記錄在設定表：遊戲目前依關卡順序（`map_id`）與玩家的進度解鎖，改這一欄不會改變遊戲的解鎖順序。

## 地圖資料檢查

- 讀取清單後列出每張地圖的資料狀態（資料完整、缺波次、缺路線、缺路線與波次），可以篩選「資料完整」「待補資料」。判斷和遊戲的「關卡資料未完成」相同（神馬三國 `utils/stagePlayability.ts` 的 `stageDataProblem`）。
- 選取地圖時顯示缺少的資料與每一波的出兵判讀（敵軍預覽 `utils/stagePreview.ts`，需要敵人設定）。
- 「資料完整」不代表玩家已解鎖，也不保證每一波都能出兵或過關；實際出兵以遊戲（`GameMap`／`WaveManager`）為準。
- 「目前畫面（草稿）」用畫面上的地圖與波次檢查（尚未保存的修改也算），並標示地圖或波次有沒有尚未保存的修改。
- 清單還沒讀取或讀取失敗時，不會顯示成 0 張。

## 素材：轉換下載與加入遊戲

- 正式網站是靜態網站（GitHub Pages），沒有上傳服務。「素材轉換」在瀏覽器把圖片轉成 WebP，預覽後下載；不會上傳，也不會加入素材選單或存進地圖。
- 讓新素材能在地圖上使用（開發流程）：
  1. 把下載的 WebP 放進 `public/images/shenmaSanguo/tiles/`（格子貼圖）或 `maps/`（地圖背景）：網頁編輯器的素材選單讀這兩個目錄。
  2. 同一個檔案放進 Godot 專案的 `godot/shenmaSanguo/assets/tiles/` 或 `assets/maps/`：遊戲從 `res://assets` 載入，網站的 `public` 不會自動打包進遊戲。
  3. 依 `scripts/shenma-regression/README.md` 重新匯出 Godot 產物並跑素材引用檢查（`tools/check-assets.mjs`），再發布。
- 本機開發（`npm run dev`）另外有「加入開發素材（本機）」：寫進本機的 `public`（`api/upload`），只加入這個頁面的素材選單；遊戲仍要做上面的第 2、3 步。
